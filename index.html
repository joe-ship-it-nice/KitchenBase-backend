👨‍🍳 KitchenBase API 👨‍🍳

Behold, a basically non-dysfunctional API for Joe-m Masak Restaurant

where no meat is served to vegetarians, and no pork is served to Halal consumers.

Getting started

Locally, the default is http://localhost:3000.

GET requests can be opened in a browser or Postman. For POST requests in Postman, choose Body → raw → JSON.

Send POST requests in Postman. These assignment endpoints do not require a login.

API features

  • View all recipes or find a recipe by ID.
  • Add recipes and authors.
  • Browse halal, non-halal and vegetarian categories.
  • Store records in a Supabase PostgreSQL database.
  • Link recipes to users and categories using foreign keys.
  • Validate input and return JSON error messages.

GET /recipes

No request body is needed. Returns an array of recipe objects.

Example response, shortened to one record:

[
    {
        "id": 1,
        "name": "Halal Chicken Rice",
        "ingredients": "Halal-certified chicken, rice, ginger, garlic, salt",
        "author": 1,
        "category": 1,
        "instructions": "Using halal ingredients and utensils, cook the chicken thoroughly. Cook rice with ginger and garlic. Serve together."
    },
    {
        "id": 2,
        "name": "Pork Fried Rice",
        "ingredients": "Pork, rice, egg, garlic, soy sauce",
        "author": 2,
        "category": 2,
        "instructions": "Cook the pork thoroughly. Add garlic and egg, then stir-fry with rice and soy sauce."
    },
    {
        "id": 3,
        "name": "Vegetable Stir-Fry",
        "ingredients": "Broccoli, carrots, mushrooms, garlic, vegetable oil, salt",
        "author": 3,
        "category": 3,
        "instructions": "Heat vegetable oil. Add garlic and vegetables. Stir-fry until cooked and season with salt."
    }

The actual response wraps the recipe objects in an array: [{...}, {...}]. An empty table returns [].

GET /recipes/:id

Replace :id with a positive integer. For example: /recipes/1.

Returns one recipe object with the same fields shown above. An invalid ID returns 400; a missing recipe returns 404.

POST /recipes

All five fields below are required:

  • name: non-empty text.
  • ingredients: non-empty text.
  • author: an existing user's integer ID.
  • category: an existing category's integer ID.
  • instructions: non-empty text.

Example JSON request:

{
  "name": "Vegetable Fried Rice",
  "ingredients": "Rice, carrots, peas, soy sauce, vegetable oil",
  "author": 1,
  "category": 3,
  "instructions": "Cook the vegetables, add rice and soy sauce, then stir-fry."
}

Check /users and /categories for valid IDs before submitting.

Returns 201 and the saved recipe object, including its generated id.

GET /users

Returns an array of users.

Example response:

[
    {
        "id": 1,
        "username": "Joe",
        "email": "joe@food.com"
    },
    {
        "id": 2,

        "email": "joel@food.com"
    },
    {
        "id": 3,
        "username": "Joseph",
        "email": "joseph@food.com"
    }
]

An empty table returns [].

POST /users

Requires a non-empty username and a valid email. Both must be unique.

Example JSON request:

{
  "username": "ChefJo",
  "email": "chefjo@food.com"
}

Returns 201 and the saved user's id, username and email. A duplicate username or email returns 409.

GET /categories

Example response using the initial category records:

[
  { "id": 1, "name": "halal" },
  { "id": 2, "name": "non-halal" },

Error responses

Status Meaning
400 Invalid input, malformed JSON, or nonexistent author/category
404 Recipe or endpoint not found
409 Username or email already exists
413 Request body exceeds the 100 KB limit
500 Unexpected server or database error

Example error body:

{
  "message": "Recipe not found."
}

Using Foreign Keys to Connect Tables

Each recipe connects to a user and a category through two foreign keys: author and category.

Foreign key References Purpose
recipe.author users.id Identifies the user who created the recipe.
recipe.category categories.id Identifies the recipe's food category.

In our sample data, Halal Chicken Rice has author = 1 and category = 1. These values link it to Joe in the users table and halal in the categories table.

Multiple recipes can share the same author or category. However, every author and category ID must exist in its referenced table. The database rejects invalid links.

Viewing the connected records

Run this SQL in Supabase's SQL Editor to display recipes alongside their author names and category names: 

SELECT
  recipe.id,
  recipe.name,
  users.username AS author_name,
  categories.name AS category_name
FROM public.recipe
JOIN public.users
  ON recipe.author = users.id
JOIN public.categories
  ON recipe.category = categories.id
ORDER BY recipe.id;

The foreign keys enforce valid relationships. The JOIN query uses those relationships to display information from all three tables together.
